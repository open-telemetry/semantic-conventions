# Semantic conventions for network interface metrics

**Status**: [Development][DocumentStatus]

These metrics describe traffic, drops, and queue occupancy on physical and virtual network interfaces.
Use resource attributes to identify the monitored device and, when needed, the interface namespace.
The same interface name can appear on multiple devices or in multiple namespaces.

Report counters only when the source measures the same set of packets as the metric definition.
For example, an outbound transmission-request counter that includes unsent packets cannot be
used directly as a transmitted-packet counter. If a source provides only an aggregate, do not
report an overlapping breakdown alongside it.

| Name | Instrument Type | Unit (UCUM) | Description | Stability | Entity Associations |

| `network.packets` | Counter | `{packet}` | The number of packets transferred by a network interface. [1] | ![Development](https://img.shields.io/badge/-development-blue) | |

**[1]:** On receive, count packets delivered to the next layer. On transmit, count packets sent by the interface. Do not use transmission-request counters that include unsent packets. ## Metric: `network.packet.dropped`

This metric is [recommended](../general/metric-requirement-level.md#recommended).

| Name | Instrument Type | Unit (UCUM) | Description | Stability | Entity Associations |
| -------- | --------------- | ----------- | -------------- | --------- | ------ |
| `network.packet.dropped` | Counter | `{packet}` | The number of packets dropped by a network interface. [1] | ![Development](https://img.shields.io/badge/-development-blue) | |

**[1]:** Count packets that the interface does not transmit or deliver to the next layer because they were discarded or encountered an error. Do not substitute a count of error events unless it counts each affected packet once. For each interface and direction, report either a total or a complete, non-overlapping breakdown by drop reason and error type, not both. Do not add a reason-specific counter to a total that already includes it.

`network.packet.drop.reason` has the following list of well-known values. If one of them applies, then the respective value MUST be used; otherwise, a custom value MAY be used.

| Value | Description | Stability |
| --- | --- | --- |
| `discarded` | The packet was deliberately discarded for a reason other than a packet error or an unsupported protocol. | ![Development](https://img.shields.io/badge/-development-blue) |
| `error` | A detected error prevented the packet from being transmitted or delivered to the next layer. | ![Development](https://img.shields.io/badge/-development-blue) |
| `unknown_protocol` | The received packet was discarded because the protocol was unknown or unsupported. | ![Development](https://img.shields.io/badge/-development-blue) |
