# Semantic conventions for network interface metrics

**Status**: [Development][DocumentStatus]

These metrics describe traffic, drops, and queue occupancy on physical and virtual network interfaces.
Use resource attributes to identify the monitored device and, when needed, the interface namespace.
The same interface name can appear on multiple devices or in multiple namespaces.

Report counters only when the source measures the same set of packets as the metric definition.
For example, an outbound transmission-request counter that includes unsent packets cannot be
used directly as a transmitted-packet counter. If a source provides only an aggregate, do not
report an overlapping breakdown alongside it.

## Metric: `network.packets`

This metric is [recommended](../general/metric-requirement-level.md#recommended).

Series with `network.packet.drop.reason` count dropped packets. Series without it count
transferred packets. If a source does not report drop counts, omit the drop series rather than
reporting zero.

| Name | Instrument Type | Unit (UCUM) | Description | Stability | Entity Associations |
| -------- | --------------- | ----------- | -------------- | --------- | ------ |
| `network.packets` | Counter | `{packet}` | The number of packets transferred or dropped by a network interface. [1] | ![Development](https://img.shields.io/badge/-development-blue) | |

**[1]:** A transferred packet is one delivered to the next layer on receive or sent by the
interface on transmit. A dropped packet does not complete that transfer because it was
discarded or encountered an error. Count each packet once for a given interface and
direction. Do not map a source counter that mixes both outcomes directly to this metric.
For example, a transmission-request counter can include unsent packets. Do not use a count
of error events unless it counts each dropped packet once.

For transferred packets and dropped packets separately, report either a total or a
complete, non-overlapping breakdown. Do not report a total alongside a breakdown
that it includes.

**[2] `error.type`:** Use a low-cardinality type for a detected error. MUST NOT be set for transferred packets, non-error discards, or a total combining error drops and non-error discards.

**[3] `network.packet.addressing`:** When reporting a breakdown by destination addressing category.

**[4] `network.packet.addressing`:** Classify the packet at the observed interface layer, not at an inner encapsulated layer. Omit this attribute when reporting the total across all addressing categories.

**[5] `network.packet.drop.reason`:** MUST be omitted for transferred packets. Use `unknown` when the source identifies dropped packets but does not report a reason or provides only a total across reasons. Use `unknown_protocol` only for receive-side drops.

## Metric: `network.interface.queue.size`

This metric is [opt-in](../general/metric-requirement-level.md#opt-in).

For transmit queue occupancy, set `network.io.direction` to `transmit`.
